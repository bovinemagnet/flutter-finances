= Client application
Paul Snow
:revnumber: 0.0.0

The Flutter client lives in `apps/finance_app` and targets Linux, Windows, macOS, iOS and Android. It is a thin application layer over two Dart packages: `finance_core` (financial rules) and `finance_store` (persistence, vault, backup and sync client; see xref:architecture:local-store.adoc[]).

Dependencies point downwards: screens and features use `AppState`; `AppState` uses `FinanceStore` and `finance_core`; platform adapters are injected through `AppServices` and are the only code that touches operating system plugins (`cunning_document_scanner`, `image_picker`, `file_selector`, `receive_sharing_intent`, `flutter_local_notifications`, `workmanager`, `flutter_secure_storage`, `google_mlkit_text_recognition`, `flutter_web_auth_2`, `local_auth`).

== State management

State is held in `AppState`, a `ChangeNotifier`, and exposed to the widget tree by `AppScope`, an `InheritedNotifier<AppState>` (`app/app_scope.dart`). Widgets call `AppScope.of(context)` and rebuild when the notifier fires; device services are read with `AppScope.servicesOf(context)`.

[NOTE]
====
The product requirements document proposes Riverpod as the state management choice, subject to a prototype. The plain notifier was chosen instead as the simpler option: the application has a single workspace-wide state object and the framework's own `InheritedNotifier` is enough to share it. Riverpod is not a dependency of `finance_app`.
====

Every write goes through `FinanceStore`, which saves the change and its outbox command in one transaction; `AppState` then drops its derived caches (the `Chart` of accounts and categories and the `LedgerProjection`) and notifies listeners. Figures are always recomputed from journals and persisted plans, never stored as editable balances. `AppState.refresh()` is called after anything outside the class changes the store, such as a sync pull. `AppState.unsyncedCount` and `isUnsynced` expose outbox state so screens can show the unsynced indicator.

== Theme and fonts

The theme is built in `app/theme.dart`. `FinancePalette` is a `ThemeExtension` with dark and light token sets (background, sidebar, card, text, muted, the mint accent, amber warning tokens and others). `buildTheme(brightness, highContrast:)` maps a palette to a Material 3 `ColorScheme` and component themes, and attaches the palette so widgets read it with `FinancePalette.of(context)`. `MaterialApp` is given light, dark, high contrast light and high contrast dark themes, so the system settings choose between them. See xref:platform:visual-design.adoc[] for the tokens and their values.

Inter, Space Grotesk and JetBrains Mono are bundled under `assets/fonts` and never fetched at run time. `app/font_licences.dart` registers their SIL Open Font Licence files with `LicenseRegistry`, so they appear on the licences page. `SectionLabel` (`app/section_label.dart`) renders the small spaced capital labels.

== Dependency wiring

`main()` in `lib/main.dart` builds the dependencies once:

. Detects `PlatformCapabilities`.
. Resolves the workspace directory as `<application support directory>/workspace`.
. Builds `AppServices`: a `FallbackReceiptScanner` (native document scanner, falling back to a basic camera or library picker), `PlatformFileImporter`, a `PluginShareInbox` when the platform has a share target (otherwise an empty one), `LocalNotifications`, and a text recogniser (ML Kit on mobile, Tesseract on desktop, or an unavailable stub when no on-device OCR exists).
. Creates a `WorkspaceGate` over the directory and `PlatformSecureKeyStore`.
. When the workspace is ready, creates a `SyncController`, starts it, and on Android and iOS registers the hourly Workmanager job for a synced workspace (see <<sync-in-the-client>>).

`FinanceApp` shows `StartupScreen` until it supplies an `AppState`, then `HomeScreen`. The `AppScope` wraps the whole `MaterialApp`, with locale `en_AU` and supported locales `en_AU`, `en_GB` and `en_US`.

== Startup, onboarding and restore

`StartupScreen` asks `WorkspaceGate.inspect()` what is on disk, by reading the plaintext `workspace.json` descriptor:

[cols="1,3",options="header"]
|===
| Status | Behaviour

| `none` | No workspace. The gate checks `newWorkspaceNeedsPassword()` (true when the platform key store fails its write and read probe, as on a Linux desktop without a Secret Service provider) and starts the five-step onboarding flow. On finishing, `WorkspaceGate.create` selects key protection, `FinanceStore.create` makes the workspace, and `AppState.applyOnboarding` writes the chosen categories, accounts, opening balances, budget plan and recurring schedules through the normal store commands.
| `platformProtected` | The data key is in the platform key store. The workspace opens without a prompt. If the key is unavailable the screen fails with a message directing the user to restore from a backup.
| `locked` | The data key is wrapped with a password (Argon2id). The user enters the password to unlock.
|===

`ConnectScreen` is the other option on a fresh device: see <<sync-in-the-client>>. The restore path (`RestoreScreen`) is offered from the startup screen. The user picks a backup file and enters the recovery secret; `WorkspaceGate.stageBackup` calls `stageRestore`, which restores into an isolated staging directory and verifies it. The screen shows the preview (counts, checksum failures, missing assets) and only offers activation when the preview allows it. Details are in xref:architecture:local-store.adoc#restore-staging[Restore staging] and xref:operations:backup-and-restore.adoc[].

Backups are exported from the settings page with `exportBackup` (see xref:domain:exports-and-backups.adoc[]).

== Sync in the client

Sync is optional and is driven by `SyncController` (`lib/data/sync_controller.dart`), a `ChangeNotifier` that wraps `SyncClient` from `finance_store` and an `OidcSession`. See xref:sync:sign-in.adoc[] for sign-in and xref:sync:offline.adoc[] for how the client behaves while syncing.

* *Settings.* The server address, the sign-in provider address and the application identifier (default `finance-app`) are kept in `sync-settings.json` in the application support directory. They are configuration for this device, not finance data, so they are never synced.
* *Turning it on.* In the settings page, the sync section (`features/sync/sync_section.dart`) signs the user in, lists the account's server workspaces and lets the user choose one or create a new one. The controller registers this device, asks `SyncClient.previewBootstrap` what would happen, and shows the answer before anything moves: upload this device's saved changes, download the server's data, start empty, or refuse when both sides already hold data (they are never merged automatically). Only a confirmation calls `enableSync`.
* *Fresh device.* `ConnectScreen` ("Use my synced data") creates an empty local workspace, signs in, picks the server workspace and downloads it. If anything fails, the empty local workspace is removed so first-time setup can run again. A workspace in a currency the client does not support is refused.
* *When it syncs.* On "Sync now", when the application returns to the foreground, and every two minutes while it is open and the workspace is synced. A sync already in progress is not started twice.
* *Failures.* An authentication failure asks the user to sign in again. Any other failure leaves the changes in the outbox, shows "Sync paused" and is retried at the next opportunity.
* *Conflicts.* The settings page shows how many changes need a decision. `ConflictsScreen` lists each one with "Yours" and "Server" summaries and offers "Keep server version", "Keep mine" (sent again as a fresh change, not offered for a change the server refused) and, for journals, "Edit a combined version", which opens the entry form on the server's version and saves the result as one validated correction. Nothing is settled by last write wins.
* *Background work.* `lib/background_sync.dart` is the Workmanager entry point. It runs only on Android and iOS, only for a synced workspace protected by the platform key store (nobody is present to type a password), and only when a refresh token is stored. It opens the store, runs one sync flagged as a metered connection and closes it again. A failure is retried later. Desktop platforms sync only while the application is open.
* *Signing out* stops the timer and deletes the stored refresh token. The data stays on the device.

== Testing

Tests are in `apps/finance_app/test` under `unit`, `widget` and `support`.

`unit/sync_controller_test.dart` covers the controller, and `widget/app_lock_test.dart` the app lock. The sync client is also tested against the real server by the end-to-end suite described in xref:ROOT:developer-guide.adoc#end-to-end-tests[the developer guide].
