= Platform capability matrix
Paul Snow
:revnumber: 0.0.0

The application asks what the device can do rather than which operating system it runs. `PlatformCapabilities.forPlatform` is the only place that inspects the platform, and platform adapters implement the interfaces in `apps/finance_app/lib/platform`.

== Matrix

[cols="2,^1,^1,^1,^1,^1",options="header"]
|===
| Capability | iOS | Android | Windows | macOS | Linux

| Native document scanner | Yes | Yes | No | No | No
| Camera fallback | Yes | Yes | No | No | No
| On-device OCR | Yes | Yes | Conditional ^1^ | Conditional ^1^ | Conditional ^1^
| Share target | Partly ^2^ | Yes | No | No | No
| Drag and drop | No | No | Yes | Yes | Yes
| Paste | Yes | Yes | Yes | Yes | Yes
| File capture | Yes | Yes | Yes | Yes | Yes
| Background work | Yes ^3^ | Yes ^3^ | No ^3^ | No ^3^ | No ^3^
| Platform key store | Yes | Yes | Yes | Yes | Conditional ^4^
| App lock | Yes ^6^ | Yes ^6^ | Yes ^6^ | Yes ^6^ | No ^6^
| Notifications | Yes ^5^ | Yes ^5^ | Yes ^5^ | Yes ^5^ | Yes ^5^

The native document scanner (`NativeDocumentScanner`, one plugin) uses VisionKit on iOS and the ML Kit document scanner on Android. Where it is missing or its resources are not yet downloaded, `FallbackReceiptScanner` uses the basic camera capture (A05). On desktop `cameraCapture` is false, so the fallback scanner opens an image picker instead of a camera. Receipts also come in through file capture, paste and drag and drop, which keep working when camera or photo access is denied. See xref:receipt-capture.adoc[].

The capabilities are computed by `PlatformCapabilities.forPlatform`: mobile means Android or iOS, and every other platform is treated as desktop. Mobile platforms get the scanner, camera, share target and background work, and desktop platforms get drag and drop. Paste, file capture and the platform key store are reported as available everywhere. Notifications are not part of the capability object; `LocalNotifications` is configured for Android, iOS, macOS, Linux and Windows.

[NOTE]
====
. Desktop OCR requires Tesseract with English language data (`eng`), detected at start-up. Without it, on-device OCR is unavailable on desktop.
. On Android the share target is implemented (`PluginShareInbox`). On iOS the app side that reads shared files exists, but the share extension needs its own Xcode target and an App Group, and that target has not yet been added to the repository; a Flutter screen alone does not implement it. The extension is expected to copy files into the App Group container and open the app, which then reads them.
. Background work is the Workmanager plugin on Android and iOS only (`WorkmanagerScheduler`). Once a workspace is synced, the application registers an hourly periodic task with a network-connected constraint; the task (`lib/background_sync.dart`) syncs only a workspace protected by the platform key store (see xref:architecture:client-application.adoc#sync-in-the-client[Sync in the client]). Desktop platforms are foreground-only (`ForegroundOnlyScheduler` does nothing): queued work resumes when the application starts, when it returns to the foreground and every two minutes while its window is open. Nothing depends on background execution succeeding.
. Linux key store availability depends on a Secret Service provider, checked at runtime. If none is available the password-based fallback is required; a plaintext key is never written (SEC 02).
. Notifications are scheduled locally and delivery is best effort, because the operating system controls it. The in-app calendar remains the authoritative record. Notification text hides amounts and merchants unless the user opts in, and a bill reminder can also be given quiet hours.
. The optional app lock uses the `local_auth` plugin (`lib/app/app_lock.dart`) and is offered in settings only when the device reports that it supports device authentication (biometrics or the device passcode). That follows the plugin's platforms: Android, iOS, macOS and Windows, but not Linux. The lock hides the interface on launch and after the application has been in the background for five minutes; it gates the screen only, and the data key stays protected by the platform key store. On Linux there is no app lock, but a workspace protected by a password asks for it on every launch.
====

Builds must be produced on each operating system. See xref:building-and-releasing.adoc[].

== Planned validation

Flutter does not guarantee that a given plugin works on every target. The requirements call for validating native dependencies, minimum operating system versions and architectures (x64 and ARM64) before advertising support. Ubuntu LTS is the proposed Linux baseline, with other distributions best effort.
